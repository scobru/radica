# Radica — domain language

Terms code and reviews use. Keep exact.

## Chat

- **Conversation** — one chat as the user sees it, named by room id: direct message (`<pk>:<pk>`, two public keys sorted), Secret Chat (`secret_…`), private room or channel (`priv_…`, `privroom_…`, River), community chat (`comm_…`).
- **Conversation state** — module answering, per conversation, everything not message text: when each message burns, how far each side has read, who is typing, TTL in force. Messenger and Classic both read it; neither keeps its own copy.
- **Read mark** — how far *I* have read (timestamp): later of this device's mark and the one my other devices left in my inbox log. Unread = others' messages after it. Never-read conversation counts from its start if direct message or Secret Chat (someone wrote to me); counts nothing if room or community (history is not news; joining sets read mark to "now"). Kept by Conversation state.
- **Peer read mark** — how far *the other person* in a direct message or Secret Chat has read. Drives ✓✓ "read" checks.
- **Secret Chat** — a one-to-one conversation sealed with the Double Ratchet (`secretRatchet.ts`, `secret:v2:`), stored only on this device. A message key opens its message once and is deleted, so the plain text is kept on the device (`radica_secret_plain_<me>`, never in the URL hash) and burned with the message. `secret:v1:` messages (before the ratchet) still open from the identity key.
- **Secret Chat session (v2)** — one Double Ratchet per (me, peer, base key), where the base key is the starter's first ratchet key; up to 4 per peer, replies go out on the one last used. Two people who start at the same time each get a session, and both decrypt. Hybrid post-quantum: each side's ML-KEM-768 key (derived from the identity key, apart from Freenet Mail's) travels in headers until used; every later sending chain mixes a fresh ML-KEM secret into the root key.
- **Secret Chat transport** — module (`secretChatTransport.ts`) that stores, sends, reads, burns Secret Chat messages. Needs only page storage, blocklist, a room's stored messages, "deliver to these inboxes"; crypto stays in `secretChat.ts`.
- **TTL** — Secret Chat disappearing-message timer, fixed presets (Off, 10s … 24h).
- **Burn** — destroying a message whose TTL ran out: removed from local storage, announced to peer. Burns when its time comes, conversation open or not.

## Device storage

- **Page storage** — `safeStorage`: page's own key/value store. In Freenet's sandboxed shell: memory plus URL hash; browser refresh keeps only the hash.
- **Native storage bridge** — `window.__radicaNative`, injected by Android and desktop apps only (never in a plain browser tab), reachable from this sandboxed iframe. File on disk: survives full app close/reopen, unlike `window.name` or hash; `safeStorage` prefers it when present. See `apps/android/.../MainActivity.java` `NativeStorage` and `apps/desktop/src/web.rs` `native_storage_script`.
- **Durable key** — page-storage key that must outlive a browser refresh. Declared once by prefix in `durable.ts` (`DURABLE_PREFIXES`); every write is copied to the node's delegate in one package per persona (`durable:<persona>`); at sign-in the package fills in what the page lost.
- **Identity keys** — local seed, Viso session, read keys. Needed before we know who signs in, so kept on the node by their own code, outside the durable package.

## Supporters

- **Donation** — USDC sent to `RadicaSupport` on Base (`donation-contract/`). Contract forwards to treasury, adds donor's Semaphore identity commitment to its tier's group.
- **Tier** — Sprout ($1+), Root ($50+), Oak ($250+); one Semaphore group each.
- **Proof** (`RADICA-ZK-V1:` token) — Semaphore proof that "an identity in this tier's group" vouches for one Radica public key (the proof's message), fixed scope `radica-supporter-v1`. Made on the donate page (`donate-app/`), outside Freenet.
- **Claim** — proof published by its Radica key in Freenet log `supporter-claims`.
- **Attester** — bot (`attester/`) that checks claims on-chain, answers in log `supporter-receipts`. Its key is one of the receipt issuers.
- **Receipt** (`RADICA-RECEIPT-V1:` token) — tier of one Radica key, signed by a key in `RECEIPT_ISSUERS`. No transaction hash; issue time rounded to the day.
- **Supporters wall** — public opt-in list in log `supporters`; each entry is a receipt published by the key it names.
- **Viso Proof-of-Personhood (`poh:github`, `poh:google`)** — anonymous RFC 9474 Blind-RSA (`RSABSSA-SHA384-PSS-Randomized`) attestations in the persona's Viso identity contract (`poh:*` slots), optionally announced on Radica's `poh` log (`radica_poh_` durable prefix). Verified locally in WebCrypto (`ui/src/viso.ts`, `verifiedPohBadgesByAuthor`). Grants: `🛡️ Verified Human` Tier-2 Web-of-Trust badge (`ui/src/wot.ts`), `.badge-github-poh` / `.badge-google-poh` provider badges on posts/profiles/sidebar (`ui/src/main.ts`), newcomer PoW exemption, 1 anti-Sybil Greenhouse vote (`ui/src/greenhousePage.ts`).
- **Viso Persona Delegation (`DelegationProofV1`)** — dual-signed (`from_pubkey` + `to_pubkey`) handoff proof in Freenet's `delegations` log (`radica_delegation_` durable prefix), verified in `ui/src/viso.ts`. Lets a legacy or destroyed Freenet persona inherit `poh:github`, `ante` commitment tier badges (`visoAnteBits` / `anteTierOf`: `16b Seeded`, `20b Forged`, `24b Veteran`) and PoH perks from an active target Viso persona (`#delegation-box` in `ui/src/supporterPanel.ts`).

## Feed

- **Repost** — ordinary post whose caption carries another post's permalink (`#post=<id>&author=<key>`), after reposter's own words if any. Caption is signed, so the feed contract has no repost field. Reader's app draws the shared post inside the reposter's card (`repost.ts`).
- **Plain repost** — repost with no words of its own. Reposting one shares the post it shares, not the repost.
- **User Wall** (`#user=<pubkey>` / `#wall=<pubkey>`) — shareable permalink to any persona's public profile Wall (`openUserProfile` / `openAuthorWallInFeed`), shown inline in posts and chat by `caption.ts` as `↪ <Name>'s Wall`. Bios (`#sidebar-bio`, `#pp-bio`, `#uview-bio`) render full Markdown (`renderCaption`), `white-space: pre-wrap`, clickable internal/external links.
- **Single Post View** (`#single-post-modal`, `openSinglePostModal` in `ui/src/main.ts`) — standalone post reader/comment view, opened from Communities thread titles/`Open` buttons and feed timestamps/`Open post` menu items. Shares `buildPostCardHtml(..., { singleView: true })`, `bindPostCardListeners` and all three moderation layers; no duplicate card IDs (`single-card-<id>`).
- **Anchored Deep-Link Scrolling** (`ui/src/scrollAnchor.ts`, `anchorElementInViewport`) — keeps a linked post centered via `ResizeObserver`, `MutationObserver`, capture `load` events after `showMyPost`, until layout settles or user interacts; stops async media above target shifting it.
- **Long-Form Article** (`radica-article:<hash>`, `ui/src/articles.ts`, `ui/src/articlesPage.ts`, `#articles-modal`) — signed `"thought"` post whose caption references an `ArticlePayload` JSON in `media-contract`. Shown as editorial preview card in Feed; opens in distraction-free Markdown Reader (`#article=<postId>&author=<pubkey>`). Durable local drafts (`radica_article_drafts_`); edit/delete from Articles UX (re-upload updated `ArticlePayload` with `editedAt`/`coverRemoved`, update post's `radica-article:<hash>` via `post-edits`); optional newsletter dispatch via Radica Mail.
- **Folio** (`folio/`) — sibling account-free Markdown writer in this repo (no identity, no Viso persona). Publishes an `ArticlePayload` straight to `media-contract`, returns a `radica-article:<hash>` token. Pasting the token in any Radica post caption suffices: `parseArticleCaption` matches it wherever written, post renders as full Article card under the paster's own signed identity. Folio needs no Radica-specific setup.
- **Music · FreeTunes Stream & Global Mini-Player** (`ui/src/audioPlayer.ts`, `ui/src/musicPage.ts`, `#music-modal`, `#global-audio-player`) — SoundCloud-style discovery stream over FreeTunes' public directory (`freetunesDirectory()`) plus persistent bottom mini-player across all Radica views.
- **Moments Reels** (`ui/src/reels.ts`, `ui/src/reelsPlayer.ts`, `radica-video-blob:<hash>`) — vertical short-video mode inside Moments (`#media-modal`), keyboard navigation, full local/AI/curator/manual moderation.

## Linfa

- **Linfa** — how alive a persona's place in Radica is, as one reader's node counts it from the signed posts, comments, likes it holds (`linfa.ts`). Never stored, never signed: a count, so unforgeable; two readers can get two values.
- **Act** — one thing feeding a Linfa: comment given/received, like given/received, repost received, a day posted. One answer counts per person and post.
- **Trust weight** — act's worth by reader's Web-of-Trust tier of the other side: followed 1, friend of a friend ½, stranger ¼.
- **Stranger cap** — all strangers give a persona, together, is worth at most 20.
- **Age** — plant stage for a Linfa: Seed, Seedling, Sapling, Young tree, Tree, Elder tree. Not supporter Tiers (Sprout, Root, Oak): those are bought, these are grown.
- **Plant** — SVG drawn for a Linfa (`plant.ts`). Whole shape comes from persona's key; Linfa only sets how far along its life it is, so it never reshuffles.
- **Fresh growth** — leaves that appeared in the last seven days, drawn lighter.
- **Living Tree** — network-wide botanical graph (`treeGraph.ts`, `treePage.ts`, `#tree-modal`): underground roots = known personas arranged by Web-of-Trust tier, upper boughs = communities (`r/slug`) and post categories, branches = posts, leaves = replies. Vitality stage (`Seed` to `Ancient Yggdrasil`) counted locally from what this node holds, never stored.

## Greenhouse

- **Greenhouse** (`ui/src/greenhouse.ts`, `ui/src/greenhousePage.ts`, `#greenhouse-modal`) — community idea/bug voting board; supporters (Sprout, Root, Oak) and active Linfa members (Sapling+) plant seeds and cast weighted votes.
- **Greenhouse comment** (`{type:"comment", seed, text}` in `greenhouse` log, `Seed.comments`) — reply under a proposal. Same weight gate as voting; reported as `<author>:<entry id>` so normal moderation queue handles it. Author always sees own; others' dropped when author hidden/blocked or target reported or AI-held (`hideComment` argument of `foldGreenhouse`).
- **Greenhouse Permalink** (`#greenhouse&seed=<author:id>` / `#seed=<author:id>`) — deep link to a proposal, parsed by `parseGreenhouseHash`, shown inline in captions as `↪ Greenhouse proposal`, scrolled/flashed on open.
- **Greenhouse Linfa weight** (`linfaGreenhouseWeight` in `linfa.ts`) — Sybil-resistant governance weight for non-supporters (`greenhouse.ts`). Ignores Tier-0 strangers; requires `MIN_TRUSTED_RECEIVED = 2` from reader's web of trust; caps unilateral `given` (`3×`) and `posting` (`2×`) relative to trusted feedback received; maps effective Linfa to weight `1` (Sapling/Young tree `12+`), `2` (Tree `120+`), `3` (Elder tree `300+`). Effective vote/proposal weight = `Math.max(tierWeight, linfaWeight)`.

## Mail

- **Radica Mail** — built-in email client (`mailClient.ts`): split-pane inbox/sent/drafts, live search, threading, activity notifications.
- **Freenet Mail Identity** — deterministic derivation of post-quantum ML-KEM-768 and ML-DSA-65 keys from the user's secret persona key, matching official `freenet/mail` standard (`fmail-key-1:...`).
- **Native Inbox Contract ID (v1)** — 44-char Base58 `ContractInstanceId` (`blake3(INBOX_CODE_HASH || params)`); what native Freemail v0.2.x expects in "To:" and Contacts import.
- **Freenet Mail Contact Token** — exportable Contact Card string `<inboxAddress>\nverify: <word1-...-word6>`, or 43-44 char Base58 contract instance ID. Radica Mail accepts tokens directly in recipient field (bare or `alias@<token>`), parses them in contact imports, strips `verify:` clauses gracefully, registers them in local address book.
- **BIP-39 Fingerprint Words** — 6 English words from `blake3(dsaVk || kemEk)`, matching native Freemail's `fingerprint_words(&vk, &ek)`. First 3 = short key in native Freemail's footer (`key: word1-word2-word3`).
- **Mail Notifications** — `NotificationItem` (type: `"mail"`): unread emails trigger sound chime, activity bell badge, direct navigation into message view, bidirectional read-status sync.

## Moderation

- **FreeTunes check** — attester's optional pass (`attester/src/freetunes.js`, `FT_CHECK=1`): looks each track in FreeTunes directory up on MusicBrainz, files a `copyright` report in FreeTunes' `reports` contract (not Radica's `reports` log), signed by the bot's own ante identity (`ante.key`). Report-only, no model.
- **Hold** — post the AI moderation helper (`attester/src/moderator.js`) hides at once, no timeout, for everyone following Radica's moderation, by flagging its own public report `{type: "report", target, hold: true}` on `reports` log. Unlike an ordinary report (only queues for a human), a hold acts immediately; author still sees own post (`freenet.aiHeldTargets()`, `ui/src/logfold.ts` `foldAiHolds`). Only for `threat`, `illegal`, `doxxing`, `scam` with model `confidence: "high"`; `spam` never held.
- **Second opinion** — before holding (never before reporting), bot re-asks the model about that one post alone, so a post cannot talk it into holding the batch's others (`moderator.js` `confirmsHold`).
- **Category circuit breaker** — once ≥3 of a category's past holds are decided and half or more were Dismissed (false positive) rather than Removed (confirmed), bot stops holding that category, back to report-only, until humans' decisions change the ratio (`categoryDisabled`, `recordHoldOutcome`). Tracked per category in bot's own state (`attester` data dir, `moderated.json`), from maintainer's and moderators' blocklists: `report` (Remove) or `dismiss` (Dismiss) entry on each held target (`holdOutcome`).
- **Retraction** — if a held post is edited and new text no longer deserves it, bot publishes `{type: "report", target, on: false}` on its next pass, lifting hold and report together.
- **Handled Reports & Multi-Moderator Attribution** (`foldHandledReports` in `ui/src/logfold.ts`, `handledReports()` / `modDecisionFor()` in `ui/src/freenet.ts`, `#mod-handled-section`) — folds every global moderator's `blocklist/<moderator>` `report` (removed) and `dismiss` entries across `RADICA_MAINTAINER` and `modsOf(RADICA_MAINTAINER)`: attributes each resolved target to the acting moderator, prevents duplicate/blind overrides (`guardDuplicateModeration`), notifies peer global moderators when a report is handled (`notifyOtherGlobalMods`).

## Decisions

- Freenet Mail v1/v2 Dual-Format Interoperability (2026-11): native Freenet Mail (v0.2.x) runs on v1 contract system, rejects 36-char compact addresses (`invalid inbox address`). Radica computes and shows both: 44-char `ContractInstanceId` for native Freemail, 36-char address for Radica P2P.
- Living Tree Network Graph Pure Layout (2026-11-14): layout, SVG rendering, inspector HTML live in DOM-free `treeGraph.ts`; pan/zoom, time-lapse animation, DOM events live in `treePage.ts`. Enables deterministic Node unit tests (`treeGraph.test.ts`) without new contract or stored counter.
- Living Tree Growth Animation & Dynamic Activity Timeline (2026-11-14): timeline bounds (`minTs`, `maxTs`) derived strictly from genuine post/comment activity, so seed community genesis dates (e.g. 2024 defaults) don't distort it. Appearance thresholds rank-staggered across `[0.12..0.94]` so posts sprout in chronological order; physical scaling on trunk height/girth, bough extension, root depth, comment unfurling; 60 FPS via cached snapshots, ease-in-out.
- Dedicated Reddit-Style Communities (`r/slug`) Rail Page (2026-11-14): existing timeline community filtering in `#feed-view` stays; adds `#communities-modal` (`ui/src/communitiesPage.ts`) from left rail (`#open-communities-btn`, shortcut `g r`) and `#comm-reddit-view-btn`. Computes net upvote/downvote score, Hot/New/Top ranking, flairs, Card/Compact views, inline thread creation, collapsible comments, About/Rules/Mods/Directory sidebar over existing posts and community logs; no contract changes.
- Live Network Mail Delivery (2026-11): outgoing mail to 43..44 char inbox contracts fetches recipient's contract state, encrypts `DecryptedMessage` JSON via ML-KEM-768/HKDF-SHA256/XChaCha20-Poly1305, signs via ML-DSA-65, dispatches to the Freenet node via `freenet.updateAppContract(key, delta)` with `UpdateInbox::AddMessages`.
- Unified Sidebar & Modal Header Iconography (2026-11): all nav rail buttons use uniform `icon-md` SVGs matching their page/modal header SVG 1:1. Headers with dynamic text (`#blocklists-modal-title`, `#create-comm-title`) nest the label in a child `<span>`, so DOM updates write to the span and never wipe the sibling `<svg>`.
- Moments Card Gallery (`#media-modal`) Architecture (2026-11): Media Explore uses a spaced card grid (`#media-grid-container.media-grid`), client-side filter state (`all`, `photos`, `videos`, `following`), author attribution rows, caption previews via `plainMentions`, comment counts (`Object.keys(post.comments ?? {}).length`); reuses existing post/contract storage.
- Settings separated from Identity (2026-11): UI preferences (layout width, themes, translation language, offensive words mask, audio sounds) live in own Settings page; Identity stays purely cryptographic keys, Viso SSO, supporter proofs.
- Reposts live in the caption, not a contract field (2026-11): a new `contract.wasm` moves every feed to a new key, and a field outside the signed message could be altered by any peer.
- Linfa counted by each reader, not stored (2026-11): a stored counter is whatever its owner signs. No leaderboard: it would need every feed, and on a small network discourages more than it rewards.
- Both chat views stay (Messenger and Classic, 2026-11): shared chat behaviour lives in Conversation state, not either view.
- Supporter badges come only from the ZK flow (2026-11): manual flow (direct ETH/BTC addresses, hand-signed receipts) is gone, so issuing doesn't depend on the maintainer. BTC donations no longer offered; receipts issued before keep verifying.
- Durable keys travel in one package per persona, not one node entry per key (2026-11): delegate cannot list its keys; one read at sign-in suffices. On restore the page wins when it already holds a key; node only fills in missing. Durable keys flush immediately on pin toggles and pagehide/visibilitychange; private room getters await node restoration so multi-group pins persist reliably.
- Mobile stage navigation excludes message rows and composer areas (2026-11): swiping right on message bubbles to mention/tag a user never triggers back navigation to the conversation inbox.
- AI moderation holds are a flag on the bot's own report, not a blocklist action (2026-11): bot's key stays a non-moderator with no power beyond its own signed entry, so a hold is only as strong as one report; a human's Dismiss/Remove on the same queue item resolves it like any other report.
- Living Tree Mobile GPU Pan/Pinch & ViewBox Commit (2026-11-15): pan/pinch on `.radica-tree-svg` apply temporary CSS `translate3d(...) scale(...)` while pausing continuous animations (`is-interacting`), and on commit mutate `svg.setAttribute("viewBox", ...)` (`applySvgViewBoxOnly` / `viewBoxFor`) instead of regenerating SVG `innerHTML`.
- Moments Native Mobile Camera Capture (2026-11-15): touch devices and insecure/sandboxed Freenet gateway origins bypass or fall back from `navigator.mediaDevices.getUserMedia` to `<input type="file" id="media-camera-input" accept="image/*" capture="environment">`; captured photo goes through the same `stagePostMediaFile` + Desert Ant moderation pipeline.
- Native Contracts Default & Dual Private Room Architecture (2026-11): Radica uses its own MIT-licensed native contracts (`contract`, `log-contract`, `media-contract`, `delegate`) for all core social/media/identity features, and for Private Rooms and Broadcast Channels by default (`AES-256-GCM` + `X25519 ECIES`, zero-knowledge `#join_room=...&lr_key=...` invites, Viso delegation, no dependency on external River WASM re-keys). Automatic `moveToRiver` background migration removed; `river-wasm` stays as opt-in/external interoperability bridge (`#privroom-river-check`, external River invite codes).
- Open Greenhouse Governance via Sybil-Resistant Linfa (2026-11): non-supporters (no GhostKey) can plant seeds and vote once Linfa reaches Sapling (`12+`) via `linfaGreenhouseWeight()`, which rejects stranger-only and unilateral farming so Sybil rings can't spam proposals or sway votes. Effective weight = `Math.max(tierWeight, linfaWeight)`.
- 🌱 The Gardener Bot, Ban Immunity & Greenhouse ↔ GitHub Sync (2026-11-15): Radica's AI helper bot is named (`AI_REPORTERS[0]` / `GARDENER_NAME` = `"🌱 The Gardener"`). Owner and moderator ban immunity enforced (`t !== c.creator && !c.moderators.includes(t) && t !== RADICA_MAINTAINER`) in `foldCommunities`, `banMemberFromCommunity`, Messenger community drawer UI, global moderation `ban`, bot passes. Public communities can invite The Gardener as community moderator (`#comm-gardener-btn`): warns in `community-chat/<id>` on 1st offense, deletes + bans on 2nd, no WASM contract changes (private E2EE chats untouched). Added `formatSeedsForAi` (`🤖 Copy for AI` / `🤖 Copy all for AI`) and allowed `statusIssuers` (`AI_REPORTERS`) in `foldGreenhouse`, so The Gardener's `greenhousePass` syncs open proposals against GitHub commits/issues (`GITHUB_REPO` / optional `GITHUB_TOKEN`) and marks completed items `done`.
- Apps Launcher Catalog & New-Tab Launch (`ui/src/ecosystem.ts`, 2026-11-16): catalog definitions and filtering live in `ui/src/ecosystem.ts` (`ECOSYSTEM`, `LAUNCHER_APPS`, `ATLAS_SITE`, `HIVE_SITE`, `AULA_SITE`). External Freenet apps launch in a dedicated tab (`Launch ↗`), not a nested iframe: `freenet-core` serves every app shell with `X-Frame-Options: DENY` to protect each app's identity/delegate `authToken` from clickjacking and sandbox proxy confusion.
- Freenet Ecosystem Apps Launcher (2026-11-15): added `#apps-modal` (`#open-apps-btn`, shortcut `g e`) as single `railPages` hub powered by `ECOSYSTEM` and pure filtering/validation helpers (`hrefOf`, `normalizeSiteKey`, `customRecordToApp`, `filterLauncherApps`) in `ui/src/ecosystem.ts`; per-persona pins and custom contract keys persist via `durable.ts` prefixes `radica_apps_pinned_` and `radica_apps_custom_`.
