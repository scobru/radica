# Radica — domain language

Terms the code and its reviews use. Keep them exact.

## Chat

- **Conversation** — one chat as the user sees it, named by its room id: a direct message (`<pk>:<pk>`, the two public keys sorted), a Secret Chat (`secret_…`), or a private room or channel (`priv_…`, `privroom_…`, River).
- **Conversation state** — the module that answers, for a conversation, everything that is not the message text: when each message burns, how far each side has read, who is typing, the TTL in force. Both chat views (Messenger and Classic) read it; neither keeps its own copy.
- **Read mark** — how far *I* have read a conversation (a timestamp): the later of this device's mark and the one my other devices left in my inbox log. Unread = messages from others after it. A conversation never read counts from its start if it is a direct message or Secret Chat (someone wrote to me), and counts nothing if it is a room or community (its history is not news; joining one gives it a read mark of "now"). Kept by Conversation state.
- **Peer read mark** — how far *the other person* in a direct message or Secret Chat has read. Drives the ✓✓ "read" checks.
- **Secret Chat** — a one-to-one conversation sealed with the Double Ratchet (`secretRatchet.ts`, `secret:v2:`), stored only on this device. A message key opens its message once and is deleted, so the plain text is kept on the device (`radica_secret_plain_<me>`, never in the URL hash) and burned with the message. `secret:v1:` messages (before the ratchet) still open from the identity key.
- **Secret Chat session (v2)** — one Double Ratchet per (me, peer, base key), where the base key is the starter's first ratchet key; up to 4 per peer, replies go out on the one last used. Two people who start at the same time each get a session, and both decrypt. Hybrid post-quantum: each side's ML-KEM-768 key (derived from the identity key, apart from Freenet Mail's) travels in headers until used; every later sending chain mixes a fresh ML-KEM secret into the root key.
- **Secret Chat transport** — the module (`secretChatTransport.ts`) that stores, sends, reads and burns Secret Chat messages. It needs only page storage, the blocklist, a room's stored messages and "deliver to these inboxes"; the crypto stays in `secretChat.ts`.
- **TTL** — the disappearing-message timer of a Secret Chat, chosen from fixed presets (Off, 10s … 24h).
- **Burn** — destroying a message whose TTL has run out: removed from local storage (`radica_secret_burned_<me>`, durable prefix) on its local timer. Incoming sealed messages (`secret:v2:` / `secret:v1:`) start their recipient-local countdown (`burn_at`, `burn_started: true`) only upon first decryption on the recipient's device so transit latency or the sender's clock never burns unread messages or deletes them prematurely via `chat_burn` (manual deletion still sends `chat_burn` to both inboxes). Automatic expiry runs via `sweepBurns()` with `{ localOnly: true }` whether or not the conversation is open.
- **Push-to-Talk / Walkie-Talkie** (`ui/src/walkieTalkie.ts`, `radica_walkie_talkie` durable prefix) — fast 10s hold-to-talk (or short-tap hands-free 60s) E2EE voice bursts paired with a per-room opt-in Walkie-Talkie queue (`createWalkieQueue`) that chimes (`playWalkieChirp`) and auto-plays incoming voice bubbles in arrival order plus sequential voice continuation (`nextSequentialHash`).
- **Circular Video Message (`vnote`)** (`[radica-cm1:vnote:…]`, `ui/src/chatMedia.ts`) — up to 60s / 12 MiB 1:1 square E2EE video bubble cropped/transcoded to fragmented MP4 via `mediabunny` (`prepareChatVideoNote`), scanned frame-by-frame on-device by Desert Ant (`analyzeImageFile`), encrypted with poster thumbnail in `media-contract` FEC chunks, and rendered as `.cm-vnote-card` with a semantic `<progress class="cm-vnote-ring">` playback ring and progressive `MediaSource` streaming.

- **LAN mesh** (`ui/src/lanMesh.ts`, `apps/desktop/src/mesh.rs`, Android `MainActivity.startMesh`) — a second, local transport for chat beside Freenet: my own signed DM and Secret Chat messages go out as UDP broadcasts (port 47509, ≤ 60 000 bytes, re-sent for 10 min) through `__radicaNative.meshSend`; the native app posts what it hears to the page as `{ type: "radica_mesh", data }`. A packet counts only if addressed to me, in the conversation of me and its sender, signed by the sender, and not from someone I block; then it is a peer event like a BroadcastChannel one, marked `via_lan`. Always on in the native apps, never a separate chat: the transport is invisible except for the 📻 mark. Edits, burns, read marks and typing stay Freenet-only.

- **Contact card** (`ui/src/contactCard.ts`) — `radica:c1:<pubkey>:<enc_pub>:<name>`, handed over in person. Saved per persona in `radica_contact_cards_<me>` (durable). Used only when no valid signed profile is cached: the profile's `enc_pub` always wins. Unsigned on purpose: the trust is the in-person exchange. Shown and scanned as a QR code (`uqr` / `jsqr`, loaded on demand).

- **Bundled Radica** — the Radica web inside the desktop binary (`build.rs`, `radica` protocol: `https://radica.localhost/` on Windows, `radica://localhost/` elsewhere) and the APK (`assets/radica-ui`, `https://radica.local/`), without its heavy containers. Opened only on **Open without Freenet**; same native storage blob, so the same identity and chats. It still tries `127.0.0.1:7509`, so offline it runs as Local-First Storage plus the LAN mesh.

- **Nearby** (`lanMesh.ts` hellos) — signed contact cards broadcast every 15 s on the LAN while **Let people on this Wi-Fi find me** is on (per device, off by default); listed for 60 s after the last one heard. A hello proves the key, never the name: Nearby rows read "not verified".

- **Terminal chat** (`ui/cli/`) — Radica's client bundled for Node with a Node `__radicaNative` (`node-bridge.ts`: file store, UDP mesh, event bus on `globalThis`). Shared code must therefore not assume `window`, `location` or a WebSocket `close` after a failed connect.

## Device storage

- **Page storage** — `safeStorage`: the page's own key/value store. In Freenet's sandboxed shell it lives in memory, plus the URL hash, and a browser refresh keeps only the hash.
- **Native storage bridge** — `window.__radicaNative`, injected by the Android and desktop apps only (never present in a plain browser tab), reachable from this sandboxed iframe. A file on disk, so unlike `window.name` or the hash it survives the app being fully closed and reopened; `safeStorage` prefers it when present. See `apps/android/.../MainActivity.java`'s `NativeStorage` and `apps/desktop/src/web.rs`'s `native_storage_script`.
- **Durable key** — a page-storage key that must outlive a browser refresh. Declared once by prefix in `durable.ts` (`DURABLE_PREFIXES`); every write is copied to the node's delegate in one package per persona (`durable:<persona>`), and at sign-in the package fills in what the page lost.
- **Identity keys** — the local seed, the Viso session and the read keys. Needed before we know who is signing in, so they are kept on the node by their own code, outside the durable package.

## Supporters

- **Donation** — USDC sent to `RadicaSupport` on Base (`donation-contract/`). The contract forwards it to the treasury and adds the donor's Semaphore identity commitment to the group of its tier.
- **Tier** — Sprout ($1+), Root ($50+), Oak ($250+); one Semaphore group each.
- **Proof** (`RADICA-ZK-V1:` token) — a Semaphore proof that "an identity in this tier's group" vouches for one Radica public key (the proof's message), with the fixed scope `radica-supporter-v1`. Made on the donate page (`donate-app/`), outside Freenet.
- **Claim** — a proof published by its Radica key in the Freenet log `supporter-claims`.
- **Attester** — the bot (`attester/`) that checks claims on-chain and answers in the log `supporter-receipts`. Its key is one of the receipt issuers.
- **Receipt** (`RADICA-RECEIPT-V1:` token) — the tier of one Radica key, signed by a key in `RECEIPT_ISSUERS`. No transaction hash; issue time rounded to the day.
- **Supporters wall** — the public, opt-in list in the log `supporters`; each entry is a receipt published by the key it names.
- **Viso Proof-of-Personhood (`poh:github`, `poh:google`)** — anonymous RFC 9474 Blind-RSA (`RSABSSA-SHA384-PSS-Randomized`) attestations stored in the persona's Viso identity contract (`poh:*` slots) and optionally announced on Radica's `poh` log (`radica_poh_` durable prefix). Verified locally in WebCrypto (`ui/src/viso.ts`, `verifiedPohBadgesByAuthor`), granting a `🛡️ Verified Human` Tier-2 Web-of-Trust badge (`ui/src/wot.ts`), visible `.badge-github-poh` / `.badge-google-poh` provider badges across posts/profiles/sidebar (`ui/src/main.ts`), newcomer PoW exemption, and 1 anti-Sybil Greenhouse vote (`ui/src/greenhousePage.ts`).
- **Viso Persona Delegation (`DelegationProofV1`)** — dual-signed (`from_pubkey` + `to_pubkey`) handoff proof stored in Freenet's `delegations` log (`radica_delegation_` durable prefix) and verified in `ui/src/viso.ts`, allowing a legacy or destroyed Freenet persona to inherit `poh:github`, `ante` commitment tier badges (`visoAnteBits` / `anteTierOf` for `16b Seeded`, `20b Forged`, `24b Veteran`), and PoH perks from an active target Viso persona (`#delegation-box` in `ui/src/supporterPanel.ts`).

## Feed

- **Repost** — an ordinary post whose caption carries the permalink of another post (`#post=<id>&author=<key>`), after the reposter's own words if any. The caption is signed, so the feed contract has no repost field. The reader's app draws the shared post inside the reposter's card (`repost.ts`).
- **Plain repost** — a repost with no words of its own. Reposting one shares the post it shares, not the repost.
- **User Wall** (`#user=<pubkey>` / `#wall=<pubkey>`) — a shareable permalink to any persona's public profile Wall (`openUserProfile` / `openAuthorWallInFeed`), formatted inline in posts and chat by `caption.ts` as `↪ <Name>'s Wall`. User profile bios (`#sidebar-bio`, `#pp-bio`, `#uview-bio`) render full Markdown (`renderCaption`) with preserved newlines/spaces (`white-space: pre-wrap`) and clickable internal/external links.
- **Comment history** (`ui/src/commentHistory.ts`, `commentsBy`; the 💬 Comments tab of a profile) — a persona's live comments, newest first, each with the post it answers. Comments are signed entries stored in the feed of the post they answer (`Post.comments`), not in the commenter's own feed, so it is counted from the posts this node holds (explore timeline, followed timeline, the persona's own feed), never stored: two readers can see two lists. Hidden/blocked authors, reported targets and AI holds are left out, as in the feed.
- **Single Post View** (`#single-post-modal`, `openSinglePostModal` in `ui/src/main.ts`) — standalone post reader/comment view openable from Communities thread titles/`Open` buttons and main feed timestamps/`Open post` menu items, sharing `buildPostCardHtml(..., { singleView: true })`, `bindPostCardListeners`, and all three moderation layers without duplicating card IDs (`single-card-<id>`).
- **Anchored Deep-Link Scrolling** (`ui/src/scrollAnchor.ts`, `anchorElementInViewport`) — keeps a linked post centered via `ResizeObserver`, `MutationObserver`, and capture `load` events after `showMyPost` until layout settles or the user interacts, preventing async media above the target from shifting it off-center.
- **Long-Form Article** (`radica-article:<hash>`, `ui/src/articles.ts`, `ui/src/articlesPage.ts`, `#articles-modal`) — a signed `"thought"` post whose caption references an `ArticlePayload` JSON stored in `media-contract`, rendered as an editorial preview card in the Feed and opened in a distraction-free Markdown Reader (`#article=<postId>&author=<pubkey>`), with durable local drafts (`radica_article_drafts_`), full editing/deletion from Articles UX (re-uploading an updated `ArticlePayload` with `editedAt`/`coverRemoved` and updating the post's `radica-article:<hash>` via `post-edits`), and optional newsletter dispatch via Radica Mail.
- **Folio** (`folio/`) — a sibling account-free Markdown writer in this repo (no identity, no Viso persona) that publishes an `ArticlePayload` straight to `media-contract` and hands back a `radica-article:<hash>` token. Pasting that token into any Radica post's caption is enough: `parseArticleCaption` matches it regardless of where it was written, and the post renders as a full Article card under the paster's own real, signed identity — Folio needs no Radica-specific setup at all.
- **Music · FreeTunes Stream & Global Mini-Player** (`ui/src/audioPlayer.ts`, `ui/src/musicPage.ts`, `#music-modal`, `#global-audio-player`) — SoundCloud-style discovery stream over FreeTunes' public directory (`freetunesDirectory()`) paired with a persistent bottom audio mini-player across all Radica views.
- **Moments Reels** (`ui/src/reels.ts`, `ui/src/reelsPlayer.ts`, `radica-video-blob:<hash>`) — vertical short-video player mode inside Moments (`#media-modal`) with keyboard navigation and full local/AI/curator/manual moderation.

## Linfa

- **Linfa** — how alive a persona's place in Radica is, as one reader's node counts it from the signed posts, comments and likes it holds (`linfa.ts`). Never stored, never signed: it is a count, so it cannot be forged, and two readers can get two values.
- **Act** — one thing that feeds a Linfa: a comment given or received, a like given or received, a repost received, a day posted. One answer counts per person and post.
- **Trust weight** — what an act is worth by the reader's Web-of-Trust tier of the other side: followed 1, friend of a friend ½, stranger ¼.
- **Stranger cap** — all that strangers give a persona, together, is worth at most 20.
- **Age** — the plant's stage for a Linfa: Seed, Seedling, Sapling, Young tree, Tree, Elder tree. Not the supporter Tiers (Sprout, Root, Oak): those are bought, these are grown.
- **Plant** — the SVG drawn for a Linfa (`plant.ts`). Its whole shape comes from the persona's key; the Linfa only says how far along its life it is, so it never reshuffles.
- **Fresh growth** — the leaves that appeared in the last seven days, drawn lighter.
- **Living Tree** — the network-wide botanical graph (`treeGraph.ts`, `treePage.ts`, `#tree-modal`): underground roots are known personas arranged by Web-of-Trust tier, upper boughs are communities (`r/slug`) and post categories, branches are posts, and leaves are replies. Its vitality stage (`Seed` to `Ancient Yggdrasil`) is counted locally from what this node holds, never stored.

## Greenhouse

- **Greenhouse** (`ui/src/greenhouse.ts`, `ui/src/greenhousePage.ts`, `#greenhouse-modal`) — community idea and bug report voting board where supporters (Sprout, Root, Oak) and active Linfa members (Sapling+) plant seeds and cast weighted votes.
- **Greenhouse comment** (`{type:"comment", seed, text}` in the `greenhouse` log, `Seed.comments`) — a reply under a proposal. Same weight gate as voting; reported as `<author>:<entry id>` so the normal moderation queue handles it; the author always sees their own, others' are dropped when the author is hidden/blocked or the target is reported or AI-held (`hideComment` argument of `foldGreenhouse`).
- **Greenhouse Permalink** (`#greenhouse&seed=<author:id>` / `#seed=<author:id>`) — shareable deep link to a specific proposal or voting, parsed by `parseGreenhouseHash`, formatted inline in captions as `↪ Greenhouse proposal`, and scrolled/flashed upon opening.

- **Greenhouse Linfa weight** (`linfaGreenhouseWeight` in `linfa.ts`) — Sybil-resistant governance weight for non-supporters in Greenhouse (`greenhouse.ts`). Ignores Tier-0 strangers, enforces `MIN_TRUSTED_RECEIVED = 2` from the reader's web of trust, caps unilateral `given` (`3×`) and `posting` (`2×`) relative to trusted feedback received, and maps effective Linfa to weight `1` (Sapling/Young tree `12+`), `2` (Tree `120+`), or `3` (Elder tree `300+`). Effective vote/proposal weight is `Math.max(tierWeight, linfaWeight)`.

## Mail

- **Radica Mail** — the built-in email client in Radica (`mailClient.ts`), offering split-pane inbox/sent/drafts management, live search, threading, and activity notifications.
- **Freenet Mail Identity** — deterministic derivation of post-quantum ML-KEM-768 and ML-DSA-65 keys from the user's secret persona key, matching the official `freenet/mail` standard (`fmail-key-1:...`).
- **Native Inbox Contract ID (v1)** — 44-character Base58 `ContractInstanceId` (`blake3(INBOX_CODE_HASH || params)`), which is what native Freemail v0.2.x expects in the "To:" field and Contacts import.
- **Freenet Mail Contact Token** — an exportable Contact Card string `<inboxAddress>\nverify: <word1-...-word6>` or 43-44 char Base58 contract instance ID. Radica Mail accepts tokens directly in the recipient field (bare or `alias@<token>`), parses them in contact imports, strips `verify:` clauses gracefully, and registers them in the local address book.
- **BIP-39 Fingerprint Words** — 6 English words extracted from `blake3(dsaVk || kemEk)` matching native Freemail's `fingerprint_words(&vk, &ek)`. The first 3 words form the short key displayed in native Freemail's footer (`key: word1-word2-word3`).
- **Blocked sender** (`blockMailSender`, `mailSenderKey` in `mailClient.ts`) — a sender this persona hid in Radica Mail, named by the inbox contract id after the `@` of their address (an alias is free text, the inbox is derived from their key). Their mail is not stored on sync and what is in the inbox is removed; the inbox contract still holds it, so unblocking brings it back on the next sync. Kept in the durable `radica_mail_blocked_<persona>` key, never published. Not the Radica blocklist: mail senders are ML-DSA Freemail identities, not Ed25519 personas.
- **Token record publication** (`ensureTokenRecordPublished` in `mailClient.ts`) — before a mail leaves, the sender's AFT `TokenAllocationRecord` contract (frozen v1 code from `freenet/mail`, parameters `TokenDelegateParameters { generator_public_key }`, so one per sender key) is PUT on the network if missing, or updated with the new token. The recipient's inbox contract resolves that record over the network; without it the update fails with `MissingContracts`. Freenet Mail's own UI does the same at identity creation.
- **Inbox subscription** (`watchOwnInbox` in `main.ts`, `watchMailInbox` in `freenet.ts`) — Radica subscribes to the persona's own Freenet Mail inbox (contract id kind `mail:<instance>`), so a delivery (an UPDATE by the sender) triggers a sync at once; Refresh is only a fallback.
- **Inbox publication** (`ensureInboxPublished`, `initialInboxState` in `mailClient.ts` / `freenetMail.ts`) — a persona's own Freenet Mail v1 inbox contract (frozen `freenet_email_inbox.wasm`, `INBOX_V1_CODE_HASH`, parameters `InboxParams { pub_key }`) is PUT with a signed empty state when a sync finds none on the network. Without it the address cannot be imported by Freenet Mail nor receive mail. The owner signature covers `STATE_UPDATE || owner_ek_bytes || serde_json(settings) || last_update µs`, so `settings` must stay in serde's field order. The two Freenet Mail WASM files are versioned (version, code hash, code): a PUT sends `unversionedWasm(...)`, the code alone, or the node files it under another code hash.
- **Mail Notifications** — integration with `NotificationItem` (type: `"mail"`) where unread emails trigger sound chimes, activity bell badges, and direct navigation into message view with bidirectional read status sync.

## Moderation

- **FreeTunes check** — the attester's optional pass (`attester/src/freetunes.js`, `FT_CHECK=1`): looks each track in the FreeTunes directory up on MusicBrainz and files a `copyright` report in FreeTunes' `reports` contract (not Radica's `reports` log), signed by the bot's own ante identity (`ante.key`). Report-only, no model.
- **Hold** — a post the AI moderation helper (`attester/src/moderator.js`) hides at once, no timeout, for everyone following Radica's moderation, by flagging its own public report `{type: "report", target, hold: true}` on the `reports` log. Unlike an ordinary report, which only queues the post for a human, a hold acts immediately; the author still sees their own post (`freenet.aiHeldTargets()`, `ui/src/logfold.ts`'s `foldAiHolds`). Only for `threat`, `illegal`, `doxxing`, and `scam` when the model says `confidence: "high"`; `spam` is never held.
- **Second opinion** — before holding (never before reporting), the bot re-asks the model about that one post alone, so a post cannot talk it into holding the ones around it in the same batch (`moderator.js`'s `confirmsHold`).
- **Category circuit breaker** — once at least 3 of a category's past holds are decided and half or more were Dismissed (a false positive) rather than Removed (confirmed), the bot stops holding for that category, back to report-only, until a human's decisions change the ratio (`categoryDisabled`, `recordHoldOutcome`). Tracked per category in the bot's own state (`attester` data dir, `moderated.json`), from reading the maintainer's and moderators' own blocklists for a `report` (Remove) or `dismiss` (Dismiss) entry on each held target (`holdOutcome`).
- **Retraction** — if a held post is edited and the new text no longer deserves it, the bot publishes `{type: "report", target, on: false}` on its own next pass, lifting the hold and the report together.
- **Handled Reports & Multi-Moderator Attribution** (`foldHandledReports` in `ui/src/logfold.ts`, `handledReports()` / `modDecisionFor()` in `ui/src/freenet.ts`, `#mod-handled-section`) — folds every global moderator's `blocklist/<moderator>` `report` (removed) and `dismiss` entries across `RADICA_MAINTAINER` and `modsOf(RADICA_MAINTAINER)` to attribute each resolved target to the acting moderator, prevent duplicate/blind overrides (`guardDuplicateModeration`), and notify peer global moderators when a report is handled (`notifyOtherGlobalMods`).

## Decisions

- Beyond Freenet: core first, CLI last (2026-11-23): Radica's data (signed ed25519 logs, E2E sealing, Double Ratchet) does not depend on Freenet; only the transport does (`network.ts`, `freenet.ts`, which also mix in browser APIs). If Radica ever has to run outside Freenet (a web gateway, Nostr/HTTP relays, more mesh links), the first step is a `radica-core` package of the pure modules (`crypto`, `logfold`, `lanMesh`, `contactCard`, …) behind a transport interface, as `SecretChatTransport` already does for Secret Chats; Freenet and the LAN mesh become two transports. A `radicactl` CLI (bots, LAN↔Freenet bridge, gateway, tests) is then a thin program on that core, as `attester/` already is today. Not built until a concrete need: no speculative core or CLI.

- LAN mesh is always on, not a fallback (2026-11-23): "Freenet unreachable" cannot be told from the page (the local node still answers while it has no peers), and the packet is the same sealed, signed message the public inbox log holds, so it is sent on both and the receiver dedups by id. One interface for both transports; a public "nearby" channel for strangers, if ever built, goes in its own section.

- Freenet Mail v1/v2 Dual-Format Interoperability (2026-11): Native Freenet Mail (v0.2.x) runs on the v1 contract system and rejects 36-char compact addresses (`invalid inbox address`). Radica delivers only to the 44-char `ContractInstanceId` (v1 inbox) and shows only that, as `alias@<inbox>`. The 36-char address (`FreenetMailIdentity.address`, Freenet Mail inbox v2 format) is derived but never routed to: `sendMailMessage` refuses it for anyone but this persona.
- Living Tree Network Graph Pure Layout (2026-11-14): Botanical network graph layout, SVG rendering, and inspector HTML generation live in DOM-free `treeGraph.ts` while pan/zoom, time-lapse animation, and DOM events live in `treePage.ts`, enabling deterministic Node unit tests (`treeGraph.test.ts`) without requiring any new contract or stored counter.
- Living Tree Growth Animation & Dynamic Activity Timeline (2026-11-14): Timeline bounds (`minTs`, `maxTs`) are derived strictly from genuine post and comment activity, preventing seed community genesis dates (e.g. 2024 defaults) from distorting the timeline. Appearance thresholds are rank-staggered across `[0.12..0.94]` so posts sprout progressively in chronological order, with physical scaling applied to trunk height/girth, bough extension, root depth, and comment unfurling, animated at 60 FPS via cached snapshots and ease-in-out easing.
- Dedicated Reddit-Style Communities (`r/slug`) Rail Page (2026-11-14): Community browsing keeps existing timeline community filtering in `#feed-view` intact while adding `#communities-modal` (`ui/src/communitiesPage.ts`) accessible from the left rail (`#open-communities-btn`, shortcut `g r`) and `#comm-reddit-view-btn`. Computes upvotes/downvotes net score, Hot/New/Top ranking, flairs, Card/Compact views, inline thread creation, collapsible comments, and an About/Rules/Mods/Directory sidebar directly over existing posts and community logs without contract changes.
- Live Network Mail Delivery (2026-11): Outgoing emails to 43..44 character inbox contracts fetch the recipient's contract state, encrypt the DecryptedMessage JSON via ML-KEM-768/HKDF-SHA256/XChaCha20-Poly1305, sign via ML-DSA-65, and dispatch directly to the Freenet node via `freenet.updateAppContract(key, delta)` with `UpdateInbox::AddMessages`.
- Unified Sidebar & Modal Header Iconography (2026-11): All navigation rail buttons use uniform `icon-md` SVGs that match their corresponding page/modal header SVG 1:1. Headers with dynamic text (`#blocklists-modal-title`, `#create-comm-title`) nest their label in a child `<span>` so DOM updates write to the span without wiping out the sibling `<svg>`.
- Moments Card Gallery (`#media-modal`) Architecture (2026-11): Media Explore uses a spaced card grid (`#media-grid-container.media-grid`) with client-side filter state (`all`, `photos`, `videos`, `following`), author attribution rows, caption previews rendered with `plainMentions`, and comment counts (`Object.keys(post.comments ?? {}).length`) while reusing existing post/contract storage.
- Settings separated from Identity (2026-11): UI preferences (layout width, themes, translation language, offensive words mask, audio sounds) live in their own Settings page, keeping Identity purely about cryptographic keys, Viso SSO and supporter proofs.
- Reposts live in the caption, not in a contract field (2026-11): a new `contract.wasm` moves every feed to a new key, and a field outside the signed message could be altered by any peer.
- Linfa is counted by each reader, not stored (2026-11): a stored counter is whatever its owner signs. There is no leaderboard: it would need every feed, and on a small network it discourages more than it rewards.
- Both chat views stay (Messenger and Classic, 2026-11): shared chat behaviour lives in Conversation state, not in either view.
- Supporter badges come only from the ZK flow (2026-11): the manual flow (direct ETH/BTC addresses, receipts signed by hand) is gone, so issuing does not depend on the maintainer. BTC donations are no longer offered; receipts issued before keep verifying.
- Durable keys travel in one package per persona, not one node entry per key (2026-11): the delegate cannot list its keys, and one read at sign-in is enough. On restore the page wins when it already holds a key; the node only fills in what is missing. Durable keys flush immediately on pin toggles and pagehide/visibilitychange, and private room getters await node restoration so multi-group pins persist reliably.
- Mobile stage navigation excludes message rows and composer areas (2026-11): swiping right on message bubbles to mention or tag a user never triggers back navigation to the conversation inbox.
- AI moderation holds are a flag on the bot's own report, not a blocklist action (2026-11): the bot's key stays a non-moderator with no power beyond its own signed entry, so a hold can only ever be as strong as one report, and a human's Dismiss/Remove on the same queue item resolves it exactly like any other report.
- Living Tree Force Physics (2026-11-20): post buds are a small force graph on top of the static layout. `treeGraph.ts` keeps a minimum node distance (`spreadPostEnds`) and tags each post's bud, branch, leaves and bloom with `data-sim=<index>`. In `treePage.ts`, `treeSim.ts`'s `simStep` springs each bud to that spot and pushes it away from nearby buds (inverse-square, "Node repulsion" slider 0–4) and from bough labels. `attachSim` moves the existing elements after each redraw (no `innerHTML` per frame) and keeps positions across redraws by `author:id`. New buds spring out from their bough, a bud can be dragged (pinned) and springs back when released, the loop stops once settled, and with `prefers-reduced-motion` it settles at once.
- Living Tree Mobile GPU Pan/Pinch & ViewBox Commit (2026-11-15): Pan/pinch interactions on `.radica-tree-svg` apply temporary CSS `translate3d(...) scale(...)` transforms while pausing continuous animations (`is-interacting`) and mutate `svg.setAttribute("viewBox", ...)` on commit (`applySvgViewBoxOnly` / `viewBoxFor`) instead of regenerating SVG `innerHTML`.
